Coast Internet Radio

The website for Coast Internet Radio, a small station in Newry run by my relative Jim Parr. It has been live since May 2026. I'm the only developer: I built it, host it and maintain it, unpaid.

I wrote it using online tutorials, my class notes and AI tools, which helped with debugging, research and some of the more complex code. I set up the hosting on Netlify and the Cloudflare Workers myself.

Visit coastinternetradio.com

The problem

The station's previous website offered several separate ways to listen, including a small embedded player, a direct stream link, a Streema widget and a TuneIn button, with no single obvious place to start. It wasn't designed for phones, and its stream was a plain HTTP address.

Most of Coast's listeners are middle-aged or older and not especially confident with technology, so the new site had to make listening simple: open the page and press play.

What I built

  • A live player with one large play button and a volume control
  • Now playing, coming up next and previously played tracks
  • Jim's live show times and an About section
  • Ways to listen on a phone, a smart speaker or in the car
  • Display settings for text size, high contrast, an easier-to-read font, light or dark mode, and reduced motion
  • Song request and feedback forms
  • An admin page where Jim can change content on the site himself

Decisions

Designing for the audience

Because most listeners aren't very technical, I kept everything on one page and made listening a single button. I also added text size and contrast options rather than assuming one size suits everyone.

Getting the stream onto an HTTPS site

The station's stream is only available over HTTP, and browsers block HTTP audio on a secure HTTPS page. I set up two small Cloudflare Workers that pass the audio and the track information through over HTTPS. The trade-off is that they're an extra service to keep running, and the site costs money to keep live each month.

What went wrong

Showing now playing, coming up next and previously played properly took much more work than I'd planned. My first design also didn't work well. I used AI tools to help fix some of the more awkward layout problems, but I'm still not fully happy with how it looks.

How changes are checked

Changes go live as soon as they're saved, for both me and Jim. There's no test copy of the site where changes can be tried first.

Limitations and what's next

  • The design isn't where I want it to be.
  • The admin page and the listener help feature could both be better.
  • I recently found that the visitor statistics aren't recording properly.
  • I'm planning to rebuild the site from scratch, with a test copy so changes can be checked before they go live.
